# Session Handoff — {{MISSION_NAME}} briefing

Audience: a fresh agent session starting from `GOAL.md` at the repository
root. Descriptive, not normative: `GOAL.md` wins on conflict. Replaces the
previous handoff (in git history; that mission completed {{DATE}}).

## Program context: why this mission exists

Two to five numbered points connecting this mission to the larger program.
The successor should understand not just WHAT to do but why doing it in this
order is load-bearing — this is what lets it make sane judgment calls when
reality deviates from the plan.

## Current state (verify before relying)

Numbered claims about the repo's verified state, each with the artifact or
command that proves it. The successor is expected to actually re-verify;
write these so that re-verification is one command, not archaeology.

## Governance conventions that keep working (keep them)

The accumulated process wins: commit discipline, review-before-dispatch,
rehearsal requirements, record-keeping habits. These survive missions.

## Design guidance (advisory)

Non-binding advice from the outgoing session: shapes that will probably
work, integration points to prefer, complexity to resist. Mark it advisory
so the successor can override with reasons.

## Known local quirks

Environment realities: slow suites, flaky-in-parallel tests (and whether
they pass in isolation), timing expectations, machine constraints.

## What NOT to do (paid-for lessons)

The most valuable section. Each entry is a mistake that already cost real
money, time, or evidence — with just enough context that the successor
recognizes the temptation when it reappears wearing different clothes.
Never prune this list to look tidy; it only grows or gets superseded by
explicit decision.
